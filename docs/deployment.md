# Развёртывание и проверка стабильности

Цель: один постоянно работающий процесс на Linux VPS с установленным Docker Compose.
Сервер ещё не выбран и не развёрнут. Стоимость и доступ проверяются перед заказом.

1. Клонировать учебный репозиторий на сервер.
2. Создать `.env` из `.env.example`. Заполнить `BOT_TOKEN`, при необходимости `ADMIN_USER_ID`.
3. Ограничить доступ к файлу: `chmod 600 .env`.
4. Остановить локальный бот, чтобы два процесса не читали один поток обновлений.
5. Запустить `docker compose up -d --build`.
6. Проверить `docker compose ps` и `docker compose logs --tail=50 bot`.
7. В Telegram добавить задачу и напоминание, импортировать CSV, оставить отзыв.
8. Выполнить `docker compose restart bot`; проверить сохранение задач и напоминания.
9. Наблюдать работу несколько дней, зафиксировать даты, перезапуски и ошибки.

`restart: unless-stopped` перезапускает завершившийся контейнер. Это не контроль
зависшего процесса; для учебного пилота состояние дополнительно проверяется вручную.
Публичного веб-сервера нет: исходящие запросы к Telegram через long polling.
Для сдачи используется ссылка `https://t.me/<username>`, а не URL хостинга.

Данные находятся в именованном томе `bot-data`, путь `/app/runtime/bot.db`.
Команда `docker compose down` сохраняет том; `down -v` удаляет его — не использовать
при обычном обновлении. Перед обновлением можно сделать копию через SQLite backup:

```bash
docker compose exec bot python -c "import sqlite3; a=sqlite3.connect('/app/runtime/bot.db'); b=sqlite3.connect('/app/runtime/backup.db'); a.backup(b); b.close(); a.close()"
```

Резервная копия остаётся в томе; для защиты от потери VPS её нужно отдельно сохранить
в закрытом хранилище. Не публиковать базы с пользовательскими данными в Git.
