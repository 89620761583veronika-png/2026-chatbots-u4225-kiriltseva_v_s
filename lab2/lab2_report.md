# Подключение бота к данным

## Источники и выбор

Использованы CSV для загрузки списка рабочих поручений и SQLite для постоянного хранения.
CSV удобен для переноса данных из таблицы менеджера, SQLite не требует отдельного
сервера и ключей внешнего API. `data/tasks.csv` содержит три демонстрационные задачи;
это тестовые данные, а не реальные поручения организации.

```csv
title,priority
Подготовить повестку встречи,high
Согласовать макет с заказчиком,normal
Разобрать архив проекта,low
```

Таблица `tasks`: id, user_id, title, priority, done, created_at, remind_at, chat_id, reminded.
Данные принадлежат конкретному Telegram ID. Таблица `feedback` добавлена для пилота lab3.

## Промпт и реализация

[Рабочий промпт](prompt.md) задаёт формат CSV, обработку ошибок и сохранение текущих команд.
Итоговые уточнения: весь файл проверять до записи, поддержать UTF-8 BOM, ограничить размер,
считать повторный импорт новой загрузкой и объяснять это в ответе.

Команда `/sample` присылает пример. Обработчик `document` загружает CSV, проверяет размер
и передаёт в `Storage.import_tasks`. `parse_csv` проверяет все строки. Только после
успешной валидации выполняется одна транзакция `executemany` с параметрами SQL.
Использованы стандартные модули `csv`, `io`, `sqlite3`: дополнительный pandas не нужен.

```python
rows = parse_csv(content)
with self.connect() as db:
    db.executemany('INSERT INTO tasks(user_id,title,priority) VALUES(?,?,?)',
                   [(user_id, title, priority) for title, priority in rows])
```

## Тестирование

Проверены корректный CSV и BOM, неверный заголовок, пустой CSV, плохая кодировка,
неверное число колонок и приоритет. При ошибке второй строки первая также не записывается.
Тест обработчика документа использует тестовый загружаемый файл и проверяет запись в БД.
Также проверены поиск без учёта регистра, сортировка и сохранение после повторного открытия.
[Журнал тестов](../docs/verification.md).

Ожидаемый сценарий живого демо:

1. `/sample`, отправить полученный CSV, получить «Импортировано задач: 3».
2. `/tasks`, `/search макет` — увидеть импортированные задачи.
3. Загрузить файл с priority=urgent — получить пояснение допустимых значений.
4. Перезапустить бот — убедиться, что данные сохранены.

Этот сценарий ещё не проверен в настоящем Telegram. Скриншоты и видео пока отсутствуют.
[План записи](../docs/demo.md).

## Трудности и решения

Файлы из редакторов могут содержать BOM, лишние колонки или пустые поля. Добавлены
`utf-8-sig`, проверка заголовка и числа колонок, понятные ответы вместо падения.
Полная валидация до транзакции исключает частичный импорт. Ограничения: UTF-8,
100 КБ, до 100 задач, заголовок title,priority. Повторный импорт не удаляет дубликаты.

## Выводы

Файловая интеграция и SQLite реализованы и проверены автоматическими тестами. Функции
первой лабораторной сохранены. Для сдачи остаётся показать реальные сообщения импорта,

CSV и подтверждение импорта, если участники пилота обнаружат потребность.
