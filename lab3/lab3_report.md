# Запуск и проверка продукта реальными пользователями

## Текущий статус

## Выбор и реализация деплоя

Выбран Docker + VPS: контейнер воспроизводит зависимости, том сохраняет SQLite, политика
перезапуска помогает восстановить процесс. `Dockerfile` запускает Python 3.12 от
непривилегированного пользователя. `compose.yaml` подключает `.env`, постоянный том и
`restart: unless-stopped`. Long polling не требует HTTP-сервера, webhook или ngrok.
Одновременно запускается один экземпляр с данным токеном.

[Рабочий промпт и уточнения](prompt.md). [Инструкция запуска, резервного копирования
и наблюдения](../docs/deployment.md).

Процесс: подготовить VPS → клонировать GitHub-репозиторий → заполнить .env → остановить
локальный процесс → `docker compose up -d --build` → проверить Telegram → перезапустить
контейнер → проверить SQLite и напоминания → наблюдать несколько дней.

Автотесты кода пройдены. Сборка и работа контейнера не подтверждены до доступности Docker
Engine. CI-файл подготовлен; успешный удалённый запуск GitHub Actions пока не подтверждён.

## Сбор обратной связи

`/feedback 1..5 комментарий` сохраняет отзыв в SQLite. `/stats` показывает число задач,
выполненных задач, пользователей с задачами, отзывов, уникальных авторов и среднюю оценку.
`/reviews` экспортирует CSV. Обе команды доступны только ADMIN_USER_ID.
Отзыв связан с Telegram ID; пользователь предупреждён об этом в справке.

План: пригласить 3–5 участников вручную после запуска. Каждому предложить добавить две
задачи, импортировать CSV, завершить одну задачу, настроить напоминание и написать отзыв.
Вопросы: что понравилось; что было неудобно; что улучшить; будете ли пользоваться.
Приглашения ещё не отправлены. Реальные пользовательские отзывы пока не получены.

## Анализ и улучшения

После пилота заполнить [feedback-analysis.md](feedback-analysis.md): факт, проблема,
приоритет, изменение, результат повторного теста. Затем попросить LLM реализовать
выбранное изменение, прогнать тесты, повторно развернуть бот и проверить с автором отзыва.

Уже добавленные кнопки, валидация и сохранение напоминаний являются проектными решениями
разработки, **не улучшениями по реальному фидбеку**. Их нельзя предъявлять как результат
пилота без пользовательских свидетельств.

## Трудности и решения

До создания Telegram-бота нет токена, поэтому нельзя проверить отправку сообщений.
Нет предоставленного сервера; подготовлены конфигурация и пошаговая процедура.
Автоматические тесты проверяют логику, но не доступность сервиса и устойчивость несколько дней.
