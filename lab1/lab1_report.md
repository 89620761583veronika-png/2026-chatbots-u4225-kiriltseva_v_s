# Создание Telegram-бота через LLM

## Задача и цель

Создать помощника для личных рабочих задач участников небольшой команды. Поручения
часто остаются в переписке: их трудно найти, определить срочность и проверить выполнение.
ДелоБот хранит список в привычном Telegram, выделяет приоритеты и напоминает о задачах.
Этот вариант выбран, потому что полезность можно проверить на конкретных действиях:
добавить поручение, найти его, завершить и получить напоминание.

## Использование LLM

Код подготовлен с помощью Codex по требованиям курса. [Рабочий промпт и уточнения](prompt.md)
фиксируют техническое задание: русский интерфейс, команды, SQLite, изоляция пользователей,
валидация и восстановление напоминаний. Это содержательное ТЗ текущей сессии, а не
дословная стенограмма. Исходная инструкция автора — сделать проект и лабораторные курса.
Итоговый запрос расширен проверкой доступа к чужим данным и обработкой длинных сообщений.

## Стек и реализация

Python 3.12, python-telegram-bot 22.8 с JobQueue, python-dotenv 1.2.1 и встроенный sqlite3.
python-telegram-bot обрабатывает команды и отправляет ответы; sqlite3 хранит задачи без
отдельного сервера; dotenv отделяет конфигурацию от кода. Зависимости закреплены версиями.
LLM генерирует код на этапе разработки, а не отвечает пользователям в работающем боте.

`bot.py` содержит обработчики. `storage.py` проверяет текст и приоритет, сохраняет и
изменяет данные. `/done` и `/remind` используют одновременно номер задачи и Telegram ID
владельца. Приоритеты: high → normal → low. Напоминание хранится в SQLite как время UTC
в секундах; JobQueue проверяет готовые уведомления каждые 30 секунд.

```python
# Из storage.py: изменение доступно только владельцу.
UPDATE tasks SET done=1 WHERE id=? AND user_id=? AND done=0
```

## Проверка

Автоматически проверены добавление, сортировка, поиск, завершение, сохранение после
повторного открытия БД, невозможность изменить чужую задачу, обработка команд и кнопки.
Полный журнал: [verification.md](../docs/verification.md). Всего в проекте 11 тестов,
успешно выполненных без сети Telegram.

Сценарий ожидаемого поведения, **не запись реального чата**:

| Действие | Ожидаемый ответ |
| --- | --- |
| `/add high Подготовить презентацию` | «Задача №… добавлена.» |
| `/tasks` | Номер, high, текст задачи |
| `/done <номер>` | «Задача выполнена ✅» |
| `/remind a b` | Пояснение, что нужны целые числа |

Бот создан: https://t.me/itmoftmi_kvs_bot. Локальный запуск 12.10.2026 успешен,
Telegram getMe подтвердил username; пользовательское демо ещё требуется. Скриншоты: ещё не сняты.
Видео 2–3 минуты: ещё не записано; [сценарий](../docs/demo.md).

## Трудности и решения

На Mac системный Python 3.9.6 не подходит выбранным зависимостям. Создано виртуальное
окружение на Python 3.12.14. Объекты Telegram в тестах заменены тестовыми объектами,
поэтому логику можно проверить до получения токена. Этот способ не проверяет доступ
к настоящему Telegram API и не заменяет пользовательское демо.
